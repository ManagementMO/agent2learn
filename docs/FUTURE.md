# Deferred decisions

Everything here was considered for v0.1 and deliberately left out, or discovered during v0.1 work
and parked. Each entry records **what**, **why it was deferred**, and **what evidence would justify
revisiting it** — so a later decision starts from the reasoning rather than from scratch.

This file is an append-target. Tasks throughout the implementation plan say "record this in
`docs/FUTURE.md`"; add to it as you go rather than reconstructing it at the end.

---

## Converter

### A union backend that merges text-layer extraction with OCR

**Strongest v0.2 candidate.** The 262-PDF acceptance run showed that **neither backend is a superset
of the other**: the shipped default found 16,192 words across 109 files that the alternate missed,
while the alternate found 31,170 words across 141 files the default missed. They fail on different
pages.

The shipped pipeline makes a crude whole-page decision — under the threshold, OCR the page and
discard its digital text; over it, never OCR. On **hybrid slides** (a real text layer *plus* text
baked into images) that throws away one half or the other. This is the single largest known source
of conversion loss, and it is a pipeline-design limit rather than a library limit.

**Revisit when:** someone implements extract-*and*-OCR with deduplicated merge. Expected to beat
either backend alone by a wide margin. Gate it on the same 262-PDF corpus.

### A deduplication pass over converted output

The alternate converter duplicates **31–46% of lines** on OCR'd documents — the same text emitted
twice, once from the text layer and once from OCR. Measured on the eight worst files: 52.6% of
baseline by raw word count but **92.0% by unique vocabulary**.

Duplication is actively harmful here: it inflates twins, wastes grounding context, and lets lexical
retrieval score the same span repeatedly. A dedup pass is cheap and worth doing **regardless of
backend**.

**Revisit when:** any converter work happens. This is close to free.

### `pymupdf4llm` as an alternate backend

It recovers **more raw content** on the private corpus (100% baseline vs 96.4%) and does more
selective per-region OCR than a whole-page threshold. It was not shipped because:

- it is **AGPL-3.0**, which would force the whole project to AGPL;
- its OCR path **fuses word boundaries** (`hypothesistesting`), which breaks the lexical overlap
  that `a2l check` and grounding depend on;
- it duplicates 31–46% of lines on OCR'd documents;
- excluding one course whose instructor posted image-only slides, the shipped default reaches
  **99.9%** content with **+59% headings**, and is faster on the 213 healthy-text-layer PDFs.

**Revisit when:** someone needs maximum raw recall and accepts AGPL. `ConverterBackend` makes this a
one-class change, and original source bytes are archived permanently, so twins can always be
regenerated by a better backend later. Converter choice is **not** a one-way door.

### Fused-token defect in the alternate backend

Documented so nobody rediscovers it: on OCR'd pages the alternate emits `andthe`, `acanadian`,
`hypothesistesting`, `arrangedamongalongtreesa`. Lexical retrieval cannot match a student's
"hypothesis testing" against a twin containing `hypothesistesting`, producing false
`no_matching_evidence`. Any backend must be checked for this before it becomes the default.

## Distribution and packaging

### Vendor plugin manifests (Claude Code, Codex)

v0.1 ships exactly one engine and one canonical `skills/` source. A `.claude-plugin/` manifest,
marketplace listing, or MCP server would each be a second surface to keep in sync.

**Revisit when:** the skills are stable and a specific marketplace has enough reach to justify the
duplication.

### npm / `npx skills add` as a primary install route

Deferred so the critical path stays on one runtime. The repository remains standards-installable by
any Agent Skills tool, but the tested path is the installer → `a2l init`.

**Revisit when:** the CLI install is boring and well-tested.

## Product surface

### Commands considered and cut

- **`a2l terms`** — `courses --all-terms` exposes the same discovery data without another command
  to build, test on three OSes, and support.
- **`ground --solve`** — deliberately absent, permanently. The tool assembles cited sources and runs
  an experimental evidence scan; it does not generate graded answers.

The v0.1 command surface is **frozen**. New convenience verbs go here unless implementation evidence
shows an existing command cannot satisfy a release requirement.

### Other institutions and other LMSs

The `School` protocol exists so another Brightspace institution can be added, but v0.1 officially
supports **University of Waterloo only**. Another adapter needs its own fixtures and its own
maintainer before it can be claimed. Non-Brightspace LMSs are unplanned.

## Validation still outstanding

### P1 on Windows and Linux

Same-device browser-to-API replay **passed on macOS (2026-08-25)**. The per-OS harvest logic differs
— Chrome paths, credential store, profile locations — so both remain release gates. The
*architectural* question is settled: LEARN does not bind sessions to the browser, so `api.py` on
`requests` is correct everywhere.

### Submission cases not covered by P2

The documented `mysubmissions` route **passed a supervised non-graded upload (2026-08-25)** with API
read-back. Still unproven:

- **group submissions** (`…/submissions/group/{groupId}/`) — v0.1 previews then refuses;
- closed or past-end-date folders;
- large files;
- any non-Waterloo Brightspace instance.

None of this relaxes the submission gate. `submit` ships disabled behind `a2l enable-submit` plus a
fresh per-file interactive TTY confirmation.

## Known limits worth stating plainly

- **`a2l check` is a lexical scan.** It cannot establish semantic correctness or contradiction. The
  `possible_conflict` status surfaces a candidate for human comparison and never asserts the student
  is wrong — a false contradiction would be worse than no tool, because it would lead someone to
  "correct" a right answer using their own professor's authority.
- **Citations move.** `path.md:line` is stable for ordinary navigation, but a converter change can
  shift lines. Machine-readable reports therefore pin source and derived hashes as well.
- **Licensed content is never fetched**, and no finite provider list can classify every future link
  perfectly. The guarantee is that Agent2Learn does not automatically fetch third-party targets, not
  that it can categorise them all.
